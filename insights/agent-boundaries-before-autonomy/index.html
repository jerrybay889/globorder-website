AI GOVERNANCE / AGENTIC WORK

에이전트는 자율성보다 경계를 먼저 설계해야 한다

에이전트의 가치는 많은 일을 혼자 하는 데 있지 않습니다. 조직이 허용한 범위 안에서 반복 업무를 처리하고, 중요한 판단은 정확한 사람에게 넘기는 데 있습니다.

핵심 요약

자율성은 목표가 아니라 운영 결과입니다. 먼저 데이터, 행동, 승인, 예외의 경계를 정하고 검증된 구간만 단계적으로 자동화해야 합니다.

1. 데이터 경계: 무엇을 읽고 무엇을 남기는가

에이전트가 접근할 수 있는 자료와 사용할 수 없는 정보를 먼저 구분해야 합니다. 개인정보와 비공개 사업 정보는 필요한 최소 범위로 제한하고, 외부 AI 호출 전에는 마스킹과 권한 확인이 필요합니다.

답변의 근거가 되는 문서와 실행 기록이 남아야 담당자가 결과를 재검토할 수 있습니다. 출처를 찾을 수 없는 답변은 자신 있게 채우는 대신 멈추도록 설계합니다.

2. 행동 경계: 어디까지 자동으로 실행하는가

초안 작성, 분류, 형식 변환처럼 되돌리기 쉬운 작업은 자동화하기 좋습니다. 발송, 공개, 계약, 결제, 데이터 삭제처럼 되돌리기 어렵거나 외부에 영향을 주는 행동은 별도의 승인 단계가 필요합니다.

같은 작업을 재시도할 수 있다면 중복 실행을 막는 기준도 함께 설계해야 합니다. 잘 작동하는 한 번보다 안전하게 반복되는 구조가 중요합니다.

3. 책임 경계: 언제 사람에게 넘기는가

예상하지 못한 입력, 근거 부족, 품질 기준 미달, 권한 부족은 명확한 에스컬레이션 사유입니다. 에이전트가 조용히 실패하거나 임의로 보완하지 않고 담당자에게 현재 상태와 필요한 결정을 전달해야 합니다.

처음에는 ‘자동 실행 → 사람 확인 → 예외 대응’의 3단계를 기본값으로 두고, 실제 기록이 쌓인 구간만 확인 단계를 줄입니다.

작은 범위에서 신뢰를 쌓기

첫 에이전트 프로젝트는 조직 전체를 바꾸는 과제가 아니라, 책임과 결과가 선명한 업무 하나로 시작하는 것이 좋습니다.

프로토타입에서 정상 흐름뿐 아니라 실패와 중단 조건까지 확인하면, 자동화 수준을 높일지 유지할지 근거를 가지고 결정할 수 있습니다.

GOVERNANCE FIRST

자동화할 수 있는가보다 자동화해도 되는가를 먼저 묻습니다. 승인과 예외의 경계가 선명할수록 에이전트는 더 오래 신뢰받습니다.
